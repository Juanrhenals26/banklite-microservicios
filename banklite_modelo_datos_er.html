BankLite — Modelo de datos por microservicio

USUARIO, DOCUMENTO_IDENTIDAD, VERIFICACION_KYC, EVALUACION_RIESGO (identity_db), CUENTA, LIMITE_OPERATIVO, RESTRICCION_REGULATORIA (account_db), TRANSACCION, ASIENTO_CONTABLE, CUENTA_CONTABLE (ledger_db) y TRANSFERENCIA, BENEFICIARIO, RIEL_PAGO, TRANSFERENCIA_PROGRAMADA (transfer_db) son el modelo ya implementado y normalizado en 3FN, tal como quedo definido en el documento oficial del equipo. CARDS y el resto de entidades de Fraude/Notificaciones/Compliance son la arquitectura objetivo para las siguientes entregas — todavia no tienen tablas reales. Cada microservicio tiene su propia base de datos (database-per-service): las relaciones entre entidades de distintos servicios son logicas, via IDs, no llaves foraneas de base de datos reales.
